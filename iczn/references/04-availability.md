# Chapter 4 — Criteria of Availability (Articles 10–20)

Source: https://code.iczn.org/chapter-4-criteria-of-availability/ · 4th edition 1999

This chapter answers the single most-asked question in nomenclature: *is this name available?* Availability is the gatekeeping test a name must pass before any other Article of the Code — priority (Ch. 6), homonymy (Ch. 12), typification (Ch. 13) — can even be applied to it. An unavailable name has no nomenclatural standing: it cannot be a senior synonym, cannot be a senior homonym, and cannot be validated by later use. Land here whenever a manuscript, database import, or synonymy review needs to decide whether a name published between 1758 and today can enter formal nomenclature at all. Publication itself (Arts. 8–9) is a separate, prior test — see `references/03-publication.md`; assume here that publication is already settled.

## Decision checklist (apply in this order)

1. **Published** under Arts. 8–9 (a "published work" in the Code's technical sense, with the post-2011 electronic-publication conditions met)? → `references/03-publication.md`. If no: stop, not available.
2. **After 1757** — Art. 3 excludes all pre-1758 (strictly, "not published after 1757") names from zoological nomenclature; Art. 11.1 restates the cut-off. If no: stop.
3. **Latin alphabet, ≥2 letters** — Art. 11.2, and for genus-group/species-group names specifically Art. 11.8/11.9.
4. **Binominal, consistently applied in the work** — Art. 11.4. Judged against the *work*, not the name in isolation.
5. **Used as valid when proposed**, not conditional and not a bare junior-synonym mention — Arts. 11.5, 11.6, and (for anonymous/conditional acts) Arts. 14, 15.
6. **Date-band content requirement** — which of Arts. 12 (pre-1931), 13 (1931–1960), 15 (1961–1999) or 16 (post-1999) governs, and does the publication meet that band's specific requirement (indication / description-or-definition / explicit "new" + type fixation)?
7. **Post-1999 names only**: explicit statement of intent to establish a new name (Art. 16.1) *and* explicit type fixation — type genus citation for family-group names (Art. 16.2), holotype/syntypes + depository statement for species-group names (Art. 16.4).
8. **Electronic-only publication**: was the work itself registered in ZooBank and does it carry the required ZooBank/ISSN/ISBN statements? → `references/03-publication.md`, `references/zoobank.md`.

If every applicable test is passed, the name is available and takes the authorship/date fixed by Arts. 21/50 (see `references/11-authorship.md`). Availability says nothing about whether the name is *currently valid* — see Database relevance below.

## Article 10 — Provisions conferring availability
General machinery: what makes a name or a nomenclatural act (e.g. a type fixation, a First Reviser action) available, and several special-case rulings.

- **10.1** — A name/act is available only once it satisfies Art. 10 and, where relevant, Arts. 11–20; the Commission may rule a name available by exercise of its plenary power even if a technical requirement was missed. [Art. 10.1](https://code.iczn.org/chapter-4-criteria-of-availability/article-10-provisions-conferring-availability/#art-10-1)
  - **10.1.1** — If a description is published in installments, availability attaches only once all Code requirements have actually been met, not at the first installment. [Art. 10.1.1](https://code.iczn.org/chapter-4-criteria-of-availability/article-10-provisions-conferring-availability/#art-10-1-1)
- **10.2** — Infrasubspecific names (Art. 45.5) are never available from their original publication, with one grandfather exception: pre-1961 "variety"/"form" names deemed available under Art. 45.6.4.1. If a later author uses such a name at species/subspecies rank, that later use establishes it as a *new* name dated to the later author, not the original coiner. [Art. 10.2](https://code.iczn.org/chapter-4-criteria-of-availability/article-10-provisions-conferring-availability/#art-10-2)

- **10.3** — A name for a "collective group" is treated as genus-group; a name for an ichnotaxon (trace fossil) takes whatever rank its original form establishes (genus-, family- or species-group). [Art. 10.3](https://code.iczn.org/chapter-4-criteria-of-availability/article-10-provisions-conferring-availability/#art-10-3)

- **10.4** — A uninominal name for any genus-group subdivision (however denoted — "section", "division", etc.) is a subgenus name; but a name for a species aggregate ("superspecies") is not a genus-group name at all. [Art. 10.4](https://code.iczn.org/chapter-4-criteria-of-availability/article-10-provisions-conferring-availability/#art-10-4)

- **10.5** — A name for a taxon not originally classified as an animal but later reclassified as one is available from its original date provided it meets this chapter's tests, is not excluded by Arts. 1.3/3, and is a potentially valid name under the relevant botanical/bacteriological code. [Art. 10.5](https://code.iczn.org/chapter-4-criteria-of-availability/article-10-provisions-conferring-availability/#art-10-5)

- **10.6** — Availability, once acquired, is permanent regardless of later invalidity (junior synonym, junior homonym, unjustified emendation, unnecessary substitute name, suppressed name) unless the Commission rules otherwise; this holds even if the taxon is later reclassified out of Animalia. [Art. 10.6](https://code.iczn.org/chapter-4-criteria-of-availability/article-10-provisions-conferring-availability/#art-10-6)

- **10.7** — Once a Part of the *List of Available Names in Zoology* is adopted for a group, a name in scope that is not on that List is not available, regardless of any prior availability it once had. [Art. 10.7](https://code.iczn.org/chapter-4-criteria-of-availability/article-10-provisions-conferring-availability/#art-10-7)

**Recommendations:** Rec. 10A (editors should keep a new taxon's description, illustrations and availability-conferring data together in one work, same day — advisory). Rec. 10B (authors encouraged to cite/obtain Official Register (ZooBank) registration numbers for new names and acts — advisory).
**Amended:** Rec. 10B was added by the 2012 electronic-publication amendment, reflecting the new ZooBank registration regime (see Art. 8.5, `references/zoobank.md`).

## Article 11 — Requirements
The baseline requirements every name/act must meet, independent of date band. Arts. 12–16 layer date-specific *content* requirements on top of this Article.

- **11.1** — Publication (Art. 8 sense) after 1757. [Art. 11.1](https://code.iczn.org/chapter-4-criteria-of-availability/article-11-requirements/#art-11-1)

- **11.2** — First-published spelling must use only the 26 Latin letters (j, k, w, y included); diacritics, apostrophes, ligatures, hyphens, or a numeral in a compound species-group name do not by themselves make the name unavailable (correctable under Arts. 27, 32.5.2). [Art. 11.2](https://code.iczn.org/chapter-4-criteria-of-availability/article-11-requirements/#art-11-2)

- **11.3** — A name may derive from Latin, Greek, any other language (even unwritten ones), or be an arbitrary but pronounceable letter-string usable as a word; an unpronounceable string is not a name. **Rec. 11A** (advisory): prefer proper latinization over bare vernacular words. [Art. 11.3](https://code.iczn.org/chapter-4-criteria-of-availability/article-11-requirements/#art-11-3)

- **11.4** — The *work* in which the name/act was published must consistently apply the Principle of Binominal Nomenclature (Art. 5.1); this test does not apply above family-group rank. The judgment is made about the work as a whole, not about the individual name. [Art. 11.4](https://code.iczn.org/chapter-4-criteria-of-availability/article-11-requirements/#art-11-4)
  - **11.4.1** — A work containing only family-group or genus-group names, with no associated species names, is presumed consistent with the Principle absent contrary evidence. [Art. 11.4.1](https://code.iczn.org/chapter-4-criteria-of-availability/article-11-requirements/#art-11-4-1)
  - **11.4.2** — Trinomial subspecies names count as consistent with the Principle. [Art. 11.4.2](https://code.iczn.org/chapter-4-criteria-of-availability/article-11-requirements/#art-11-4-2)
  - **11.4.3** — A pre-1931 index, even inside a non-binominal work, is itself treated as a consistently-binominal work if the index applies the Principle consistently and unambiguously links each index entry to the description/illustration/indication in the body text; a name available only via such an index is dated to that index. [Art. 11.4.3](https://code.iczn.org/chapter-4-criteria-of-availability/article-11-requirements/#art-11-4-3)
- **11.5** — A name must be used as valid for a taxon at the moment it is proposed. Two exclusions: a name first proposed as a junior synonym is unavailable *unless later rescued* under Art. 11.6.1; and, per Art. 11.5.1 below, pre-1961 conditional proposals get a pass. [Art. 11.5](https://code.iczn.org/chapter-4-criteria-of-availability/article-11-requirements/#art-11-5)
  - **11.5.1** — A name proposed conditionally before 1961 is *not* excluded from availability on that ground alone (cross-ref Art. 15 for the post-1960 rule, which is the opposite). [Art. 11.5.1](https://code.iczn.org/chapter-4-criteria-of-availability/article-11-requirements/#art-11-5-1)
  - **11.5.2** — Mere later citation of an unavailable name (without adopting it for a taxon), even with a bibliographic reference to the original work, does not make it available. Availability requires an author to actually adopt the name for a taxon. [Art. 11.5.2](https://code.iczn.org/chapter-4-criteria-of-availability/article-11-requirements/#art-11-5-2)
- **11.6** — A name first published, in an otherwise available work, as an explicit junior synonym of a name then treated as valid is *not* thereby made available. [Art. 11.6](https://code.iczn.org/chapter-4-criteria-of-availability/article-11-requirements/#art-11-6)
  - **11.6.1** — Grandfather exception: if such a synonym-published name was, before 1961, either adopted as valid or treated as a senior homonym by some author, it becomes available — but dated to its *original* (synonym) publication, not to the rescuing act. [Art. 11.6.1](https://code.iczn.org/chapter-4-criteria-of-availability/article-11-requirements/#art-11-6-1)
  - **11.6.2** — A name cited as a synonym that was itself published in the 1757–1758 window cannot be rescued under Art. 11.6. [Art. 11.6.2](https://code.iczn.org/chapter-4-criteria-of-availability/article-11-requirements/#art-11-6-2)
  - **11.6.3** — A name first published as a junior synonym *after 1960* can never be rescued under Art. 11.6 (the pre-1961 exception has a hard cutoff). [Art. 11.6.3](https://code.iczn.org/chapter-4-criteria-of-availability/article-11-requirements/#art-11-6-3)
- **11.7 — Family-group names.** Form requirements, in addition to Art. 29's suffix rules (`references/08-family-group.md`). [Art. 11.7](https://code.iczn.org/chapter-4-criteria-of-availability/article-11-requirements/#art-11-7)
  - **11.7.1.1** — Must be a nominative plural noun built on the stem of an available generic name then treated as valid in that family-group taxon (stem alone is accepted as evidence the genus was treated as valid, absent contrary evidence). [Art. 11.7.1.1](https://code.iczn.org/chapter-4-criteria-of-availability/article-11-requirements/#art-11-7-1-1)
  - **11.7.1.2** — Must clearly function as a name for a suprageneric taxon, not merely as a plural/adjective referring to a genus's species. [Art. 11.7.1.2](https://code.iczn.org/chapter-4-criteria-of-availability/article-11-requirements/#art-11-7-1-2)
  - **11.7.1.3** — Must carry a family-group suffix (Art. 29.2); an incorrect suffix does not defeat availability — it is simply corrected, keeping original authorship/date. [Art. 11.7.1.3](https://code.iczn.org/chapter-4-criteria-of-availability/article-11-requirements/#art-11-7-1-3)
  - **11.7.1.4** — Must not be built on an Art. 20 fossil-only `-ites`/`-ytes`/`-ithes` name. [Art. 11.7.1.4](https://code.iczn.org/chapter-4-criteria-of-availability/article-11-requirements/#art-11-7-1-4)
  - **11.7.1.5** — Must not be built on a genus-group name the Commission has suppressed. [Art. 11.7.1.5](https://code.iczn.org/chapter-4-criteria-of-availability/article-11-requirements/#art-11-7-1-5)
  - **11.7.2** — A pre-1900 family-group name published in non-latinized (vernacular) form is available from that original date only if later authors latinized it and the group's specialists generally accepted it as dating from the vernacular original. [Art. 11.7.2](https://code.iczn.org/chapter-4-criteria-of-availability/article-11-requirements/#art-11-7-2)
- **11.8 — Genus-group names.** Must be a word of ≥2 letters that is, or is treated as, a nominative singular noun. [Art. 11.8](https://code.iczn.org/chapter-4-criteria-of-availability/article-11-requirements/#art-11-8)
  - **11.8.1** — A name proposed in running Latin text in a non-nominative case purely because Latin grammar required it is still available, but is corrected to the nominative. [Art. 11.8.1](https://code.iczn.org/chapter-4-criteria-of-availability/article-11-requirements/#art-11-8-1)
- **11.9 — Species-group names.** [Art. 11.9](https://code.iczn.org/chapter-4-criteria-of-availability/article-11-requirements/#art-11-9)
  - **11.9.1** — Must be ≥2 letters (or a compound word under 11.9.5) and, if Latin/latinized, one of: (11.9.1.1) nominative-singular adjective/participle agreeing with the genus name; (11.9.1.2) nominative-singular noun in apposition to the genus name; (11.9.1.3) genitive-case noun; (11.9.1.4) genitive-case substantive adjective derived from an associated organism's name. [Art. 11.9.1](https://code.iczn.org/chapter-4-criteria-of-availability/article-11-requirements/#art-11-9-1)
  - **11.9.2** — Same grammatical-case rescue as 11.8.1: an adjectival name forced into a non-nominative case by Latin syntax is available, corrected to nominative. [Art. 11.9.2](https://code.iczn.org/chapter-4-criteria-of-availability/article-11-requirements/#art-11-9-2)
  - **11.9.3** — Must be published in unambiguous combination with a genus name (explicit or clear from context). [Art. 11.9.3](https://code.iczn.org/chapter-4-criteria-of-availability/article-11-requirements/#art-11-9-3)
    - **11.9.3.1** — The genus name need not itself be valid or even available.
    - **11.9.3.2** — The species name is deemed combined with the *correct original spelling* of the genus name even if actually printed with an emendation/misspelling.
    - **11.9.3.3** — An unambiguous abbreviation of the genus name is acceptable.
    - **11.9.3.4** — The combination may be tentative (e.g. "Genus? species") without losing availability.
    - **11.9.3.5** — A species name first published only as an Art. 6.2 interpolated name is not made available by that act.
    - **11.9.3.6** — A pre-1961 species name combined with an already-available genus, where the same work *also* conditionally proposes a new genus for it, is deemed available in the pre-existing genus combination (cf. Art. 15.1).
  - **11.9.4** — Must not be words joined by a conjunction, nor contain a non-latin-alphabet sign. [Art. 11.9.4](https://code.iczn.org/chapter-4-criteria-of-availability/article-11-requirements/#art-11-9-4)
  - **11.9.5** — Where a name denoting one entity (host species, place, etc.) was printed as separate words in an otherwise consistently-binominal work, the words are deemed one word, united without a hyphen (Art. 32.5.2.2); a genuine descriptive phrase not naming a single entity does not qualify. [Art. 11.9.5](https://code.iczn.org/chapter-4-criteria-of-availability/article-11-requirements/#art-11-9-5)
- **11.10** — If an author names the type species of a new genus using a species/subspecies name *deliberately as a knowing misidentification* of an earlier name, the act is deemed to establish a brand-new nominal species (own author/date) rather than to reuse the misidentified name (cross-ref Arts. 67.13, 69.2.4 for the typification consequences). [Art. 11.10](https://code.iczn.org/chapter-4-criteria-of-availability/article-11-requirements/#art-11-10)

**Database relevance:** the Art. 11.7–11.9 form tests (nominative-singular noun for genera, adjective/noun-apposition/genitive for species) are exactly what a name-parsing/validation routine should check before accepting a `scientificName` into a nomenclatural database — a string failing all three species-group forms is a red flag for a typo or a non-Code-compliant entry, not necessarily an unavailable name (grammatical correction under 11.8.1/11.9.2 may save it).

## Article 12 — Names published before 1931
- **12.1** — A pre-1931 name is available if it meets Art. 11 and is accompanied by a description, a definition, *or* merely an "indication" (defined narrowly below). [Art. 12.1](https://code.iczn.org/chapter-4-criteria-of-availability/article-12-names-published-before-1931/#art-12-1)

- **12.2** — "Indication" is a closed list, not a general permission to describe loosely:
  - **12.2.1** a bibliographic reference to an already-published description/definition (even in a pre-1758, non-binominal, or Commission-suppressed work, unless the Commission ruled that work unpublished); [Art. 12.2.1](https://code.iczn.org/chapter-4-criteria-of-availability/article-12-names-published-before-1931/#art-12-2-1)
  - **12.2.2** inclusion in an index to a non-binominal work, if Art. 11.4.3's conditions are met; [Art. 12.2.2](https://code.iczn.org/chapter-4-criteria-of-availability/article-12-names-published-before-1931/#art-12-2-2)
  - **12.2.3** express proposal as a replacement name (nomen novum) for an available name, whether or not the Code required replacement; [Art. 12.2.3](https://code.iczn.org/chapter-4-criteria-of-availability/article-12-names-published-before-1931/#art-12-2-3)
  - **12.2.4** formation of a family-group name from an available genus name (Art. 29); [Art. 12.2.4](https://code.iczn.org/chapter-4-criteria-of-availability/article-12-names-published-before-1931/#art-12-2-4)
  - **12.2.5** for a new genus name, use of one or more available species names in/under it, or bibliographically linked to it, unambiguously; [Art. 12.2.5](https://code.iczn.org/chapter-4-criteria-of-availability/article-12-names-published-before-1931/#art-12-2-5)
  - **12.2.6** a combined description/definition covering a new genus plus one new species — each name gets its own indication from the same text; [Art. 12.2.6](https://code.iczn.org/chapter-4-criteria-of-availability/article-12-names-published-before-1931/#art-12-2-6)
  - **12.2.7** proposal of a new genus- or species-group name tied to an illustration (or a bibliographic reference to one), under the same "even if in a suppressed/non-binominal/pre-1758 work" tolerance as 12.2.1; [Art. 12.2.7](https://code.iczn.org/chapter-4-criteria-of-availability/article-12-names-published-before-1931/#art-12-2-7)
  - **12.2.8** description of an organism's *work* (trace/product), e.g. for ichnotaxa. [Art. 12.2.8](https://code.iczn.org/chapter-4-criteria-of-availability/article-12-names-published-before-1931/#art-12-2-8)
- **12.3** — What never counts, alone, as a description/definition/indication: a vernacular name, a locality, a geological horizon, a host, a label, or a bare specimen citation. [Art. 12.3](https://code.iczn.org/chapter-4-criteria-of-availability/article-12-names-published-before-1931/#art-12-3)

## Article 13 — Names published after 1930
This is the sharpest date-band boundary in the Code: Art. 12's loose "indication" test ends at 1930; from 1931 on, actual differentiating content is mandatory. **Database relevance:** a `nomenclaturalStatus`/availability-audit workflow should branch on `year(dwc:namePublishedInYear) < 1931` before applying any completeness check — the same "no explicit description" fact is fatal after 1930 and immaterial before it.

- **13.1** — A post-1930 name must meet Art. 11 and either:
  - **13.1.1** be accompanied by a description or definition stating **in words** characters that purportedly differentiate the taxon; [Art. 13.1.1](https://code.iczn.org/chapter-4-criteria-of-availability/article-13-names-published-after-1930/#art-13-1-1)
  - **13.1.2** be accompanied by a bibliographic reference to such a published statement (same suppressed/non-binominal/pre-1758 tolerance as Art. 12.2.1); [Art. 13.1.2](https://code.iczn.org/chapter-4-criteria-of-availability/article-13-names-published-after-1930/#art-13-1-2)
  - **13.1.3** or be expressly proposed as a replacement name (nomen novum), required or not. [Art. 13.1.3](https://code.iczn.org/chapter-4-criteria-of-availability/article-13-names-published-after-1930/#art-13-1-3)
  - A bare genetic-distance statistic (e.g. "3.57% cytochrome-b divergence") does **not** satisfy 13.1.1 because it states no character in words; a stated nucleotide sequence purporting to differentiate the taxon does. **Amended:** the Examples illustrating this molecular-data reading of 13.1.1 were added by **Declaration 47**; Declaration 47 did not change the rule's wording, only clarified how it applies to DNA-sequence-only descriptions.
  - **Rec. 13A** (advisory): include an explicit diagnosis. **Rec. 13B** (advisory): publish diagnoses in an internationally used language, plus a regionally relevant one.
- **13.2** — A post-1930 family-group name must, in addition to 13.1, be formed from a genus name then treated as valid in that taxon (Art. 11.7.1.1, 29). [Art. 13.2](https://code.iczn.org/chapter-4-criteria-of-availability/article-13-names-published-after-1930/#art-13-2)
  - **13.2.1** — Narrow grandfather clause: a 1931–1960 family-group name that fails 13.1 is nonetheless available from its original date if it was used as valid before 2000 and no author, applying the then-current Code between 1961 and 1999, expressly rejected it under this Article. [Art. 13.2.1](https://code.iczn.org/chapter-4-criteria-of-availability/article-13-names-published-after-1930/#art-13-2-1)
- **13.3 — Genus-group names.** A post-1930 genus-group name (other than for a collective group or ichnotaxon) must, on top of 13.1, have a **type species fixed in the same original publication**, or be expressly a replacement name. [Art. 13.3](https://code.iczn.org/chapter-4-criteria-of-availability/article-13-names-published-after-1930/#art-13-3)
  - **13.3.1** — If a pre-1931 genus name is replaced post-1930 by a nomen novum, a type species must be designated then if none exists yet. [Art. 13.3.1](https://code.iczn.org/chapter-4-criteria-of-availability/article-13-names-published-after-1930/#art-13-3-1)
  - **13.3.2** — Collective-group names never need a type species (collective groups have none, Art. 42.3.1). [Art. 13.3.2](https://code.iczn.org/chapter-4-criteria-of-availability/article-13-names-published-after-1930/#art-13-3-2)
  - **13.3.3** — Genus-level ichnotaxon names published before 2000 need no type species; but a post-1999 nomen novum replacing one does require one. [Art. 13.3.3](https://code.iczn.org/chapter-4-criteria-of-availability/article-13-names-published-after-1930/#art-13-3-3)

**Database relevance:** Art. 13.3's original type-species fixation is the historical root of the `typeSpecies` field on a genus-group name record; a post-1930 genus name with no recoverable type-species fixation in its original publication is a strong availability red flag, not merely an incompleteness in the database.

- **13.4** — A combined "gen. nov., sp. nov." description covering a new genus/subgenus plus one included new species confers availability on both names under 13.1.1 (the species name, if post-1999, must *also* clear Art. 16.4). [Art. 13.4](https://code.iczn.org/chapter-4-criteria-of-availability/article-13-names-published-after-1930/#art-13-4)

- **13.5** — A combined description of a new family-group taxon plus the single new genus that founds it confers availability on both under 13.1.1 — but for post-1930 publications, *neither* name becomes available unless a type species is fixed for the genus (13.2, 13.3). [Art. 13.5](https://code.iczn.org/chapter-4-criteria-of-availability/article-13-names-published-after-1930/#art-13-5)
  - **Rec. 13C** (advisory): avoid combined descriptions; differentiate each new taxon separately.
- **13.6 — Exclusions.**
  - **13.6.1** — Post-1930 names cannot rely on the Art. 12.2.2, 12.2.4 (except via 13.2.1), 12.2.5, or 12.2.7 indication routes. [Art. 13.6.1](https://code.iczn.org/chapter-4-criteria-of-availability/article-13-names-published-after-1930/#art-13-6-1)
  - **13.6.2** — A post-1930 name based on the work of a then-*extant* animal (e.g. a nest, burrow) is outside zoological nomenclature entirely (Art. 1.3.6). [Art. 13.6.2](https://code.iczn.org/chapter-4-criteria-of-availability/article-13-names-published-after-1930/#art-13-6-2)

## Article 14 — Anonymous authorship of names and nomenclatural acts
A new name or act with anonymous authorship (Art. 50.1) published after 1950 is not made available by that publication; the same act before 1951 does not block availability. The Commission's own anonymous acts are exempt from this Article entirely. [Art. 14](https://code.iczn.org/chapter-4-criteria-of-availability/article-14-anonymous-authorship-of-names-and-nomenclatural-acts/#art-14)

## Article 15 — Names and nomenclatural acts published after 1960
- **15.1** — A name/act proposed *conditionally* and published after 1960 is not made available by that publication; a pre-1961 conditional proposal may be (cross-ref Arts. 11.5.1, 67.2.5, 67.5.3, 11.9.3.6, 51.3.3). This is the mirror image of Art. 11.5.1 — the same 1961 line, opposite direction. [Art. 15.1](https://code.iczn.org/chapter-4-criteria-of-availability/article-15-names-and-nomenclatural-acts-published-after-1960/#art-15-1)

- **15.2** — A post-1960 name expressly proposed as a "variety" or "form" is infrasubspecific by definition and entirely outside the Code (Arts. 1.1.1, 1.3.4, 45.6.3) — not merely unavailable, but unregulated. [Art. 15.2](https://code.iczn.org/chapter-4-criteria-of-availability/article-15-names-and-nomenclatural-acts-published-after-1960/#art-15-2)
  - **15.2.1** — Pre-1961 "variety"/"form" names instead follow Art. 45.6.4's grandfather rule.

## Article 16 — Names published after 1999
The strictest date band: explicit intent plus explicit type-fixation, in the original publication itself — omissions here are not curable later.

- **16.1** — Every post-1999 new name (including nomina nova) must be **explicitly** flagged as intentionally new. **Rec. 16A** (advisory): use "sp. nov.", "gen. nov.", "n. sp." etc., or "nomen novum" / "nom. nov." specifically for replacement names; avoid "stat. nov." — but if it was used to promote a former infrasubspecific name to species/subspecies rank, that usage is accepted as showing intent to establish it as new (Art. 45.5.1). [Art. 16.1](https://code.iczn.org/chapter-4-criteria-of-availability/article-16-names-published-after-1999/#art-16-1)

- **16.2 — Family-group names.** On top of Arts. 13–15, a post-1999 family-group name must cite the name of its type genus. **Rec. 16B** (advisory): cite that genus's author, date and a bibliographic reference, to avoid ambiguity with homonyms. [Art. 16.2](https://code.iczn.org/chapter-4-criteria-of-availability/article-16-names-published-after-1999/#art-16-2)

- **16.3 — Genus-group names.** Collective-group and ichnotaxon genus names follow Arts. 13.3.2/13.3.3, not a separate post-1999 rule. [Art. 16.3](https://code.iczn.org/chapter-4-criteria-of-availability/article-16-names-published-after-1999/#art-16-3)

- **16.4 — Species-group names.** Every post-1999 new species/subspecies name (other than a nomen novum, whose type is fixed automatically under Art. 72.7) must, **in the original publication**:
  - **16.4.1** explicitly fix a holotype or syntypes for the nominal taxon (Arts. 72.2, 72.3, 73.1.1, 73.2; Recs. 73A, 73C — see `references/13-typification.md`); and [Art. 16.4.1](https://code.iczn.org/chapter-4-criteria-of-availability/article-16-names-published-after-1999/#art-16-4-1)
  - **16.4.2** if the type material is extant specimens, state an intent that they will be, or are, deposited in a named collection, and name that collection's location. [Art. 16.4.2](https://code.iczn.org/chapter-4-criteria-of-availability/article-16-names-published-after-1999/#art-16-4-2)
  - **Rec. 16C–16F** (all advisory): deposit in an institution with a proper research collection (Rec. 72F criteria); publish specimen numbers/label data; prefer a holotype over syntypes; illustrate the type.

**Database relevance:** Art. 16.4.1/16.4.2 are the availability-side justification for making `typeStatus`, `typeDepository` (institutionCode of the repository) and a type-specimen catalogue number *mandatory-if-post-1999* fields on a new species-group name record — a post-1999 name record with type fixed but no depository value is not just incomplete metadata, it is evidence the underlying name may not be available at all.

**Common errors:** the single most frequent availability defect in recent (post-1999) species descriptions is satisfying 16.4.1 (naming a holotype) while omitting 16.4.2 (the collection-deposit statement) — this alone renders the name unavailable regardless of how thorough the rest of the description is. A second common defect: describing a species from tissue/DNA only, with no physical name-bearing type and no 16.4.1 fixation, which fails 16.4 outright (see also Art. 73 in `references/13-typification.md` on what may serve as a type).

## Article 17 — Names found to denote more than one taxon, or taxa of hybrid origin, or based on parts or stages of animals or on unusual specimens
Availability is unaffected — a persistent misconception is that any of the following voids the name:
- **17.1** the description or type material turns out to cover more than one taxon, or parts of animals from more than one taxon; [Art. 17.1](https://code.iczn.org/chapter-4-criteria-of-availability/article-17-names-found-to-denote-more-than-one-taxon-or-taxa-of-hybrid-origin-or-based-on-parts-or-stages-of-animals-or-on-unusual-specimens/#art-17-1)

- **17.2** the taxon is known, or later found, to be of hybrid origin (cross-ref Art. 23.8 on priority effects); [Art. 17.2](https://code.iczn.org/chapter-4-criteria-of-availability/article-17-names-found-to-denote-more-than-one-taxon-or-taxa-of-hybrid-origin-or-based-on-parts-or-stages-of-animals-or-on-unusual-specimens/#art-17-2)

- **17.3** the name is based on only part of an animal, a single sex, a single life-cycle stage, one of several dissimilar generations, one caste/morph of a polymorphic species, a parthenogenetic form, or an atypical individual (subject to the exclusions in Arts. 1.3, 45.6). [Art. 17.3](https://code.iczn.org/chapter-4-criteria-of-availability/article-17-names-found-to-denote-more-than-one-taxon-or-taxa-of-hybrid-origin-or-based-on-parts-or-stages-of-animals-or-on-unusual-specimens/#art-17-3)

**Common errors:** treating a name as unavailable because its type turned out to be a larval stage, one sex of a sexually dimorphic species, or a chimeric type series — none of that is a ground for unavailability; these are taxonomic/typification problems, handled under Ch. 13 (`references/13-typification.md`), not availability problems.

## Article 18 — Inappropriate and tautonymous names
Availability is unaffected by a name being descriptively wrong (e.g. a name implying a trait or range the taxon lacks) or by tautonymy (genus and species epithet identical, or identical across all three components of a trinomen, e.g. a hypothetical *Genus genus genus*). Cross-ref Art. 23.3.7 for the (non-)effect on priority. [Art. 18](https://code.iczn.org/chapter-4-criteria-of-availability/article-18-inappropriate-and-tautonymous-names/#art-18)

## Article 19 — Status of emendations, incorrect spellings, and mandatory changes
This Article states only the *availability* consequence of spelling events; the mechanics of which spelling is "correct" live in `references/07-formation-spelling.md` (Arts. 27, 29, 32–34).

- **19.1** — An **unjustified emendation** is itself a separately available name (Art. 33.2.3) if it independently meets availability, and is treated as a potential new name/homonym in its own right; an **incorrect subsequent spelling**, by contrast, is never separately available (Art. 33.3) — it stays a mere variant of the name it misspells. [Art. 19.1](https://code.iczn.org/chapter-4-criteria-of-availability/article-19-status-of-emendations-incorrect-spellings-and-mandatory-changes/#art-19-1)

- **19.2** — A **justified emendation** simply replaces the incorrect original spelling; as a "corrected original spelling" it keeps the original name's authorship and date — it is not a new available name. [Art. 19.2](https://code.iczn.org/chapter-4-criteria-of-availability/article-19-status-of-emendations-incorrect-spellings-and-mandatory-changes/#art-19-2)

- **19.3** — Where a name was originally published with multiple alternative spellings, whichever the First Reviser did not adopt becomes an incorrect original spelling and is not separately available. [Art. 19.3](https://code.iczn.org/chapter-4-criteria-of-availability/article-19-status-of-emendations-incorrect-spellings-and-mandatory-changes/#art-19-3)

- **19.4** — A mandatory grammatical-agreement change under Art. 34 (e.g. gender agreement of a species adjective when moved between genera) has no effect on availability. [Art. 19.4](https://code.iczn.org/chapter-4-criteria-of-availability/article-19-status-of-emendations-incorrect-spellings-and-mandatory-changes/#art-19-4)

**Database relevance:** an unjustified emendation is a *distinct available name string* that may itself need a `scientificName` row and its own homonymy check; an incorrect subsequent spelling is not — model it as a spelling variant/synonym pointer to the correctly-spelled name, never as an independent taxon-name record.

## Article 20 — Genus-group names ending in -ites, -ytes, or -ithes given to fossils
A genus-group name formed by tacking `-ites`, `-ytes` or `-ithes` onto the whole or the stem of an already-available genus name, applied to fossils simply to flag them as fossil (not extant) members of that genus, **without clear evidence the author meant to erect a genuinely new genus-group taxon**, is available *only* for homonymy purposes. It cannot be used as a valid name (Art. 23.1) and cannot found a family-group name (Art. 11.7.1.4). Names coined for genuinely distinct fossil genera (not merely to flag "this is the fossil form of Genus X") are unaffected by this Article and may be fully available. [Art. 20](https://code.iczn.org/chapter-4-criteria-of-availability/article-20-genus-group-names-ending-in-its-ytes-or-ithes-given-to-fossils/#art-20)

**Common errors:** treating every `-ites`/`-ytes`/`-ithes` genus name as automatically homonymy-only; the Article 20 restriction applies only where the name was coined merely to mark a fossil occurrence of an existing genus, not where it names a taxonomically distinct fossil genus (the Code's own example: *Pentacrinites* is a real, fully available genus name, not a flagging suffix).

## Database relevance

**Availability and validity are different axes and belong in different database fields.**

- **Availability** is a permanent, binary, name-centric property established once, at (or shortly after) original publication, by the tests in this chapter. It never changes with later taxonomic opinion — a name does not become "unavailable" because a revision now treats it as a junior synonym (Art. 10.6). It can only be altered by a Commission ruling (suppression, or a ruling of availability under the plenary power). Model this as **Darwin Core `nomenclaturalStatus`** on the *name* record (e.g. `nomen nudum`, `nomen novum`, `available`, `unavailable`) — a property of `scientificName`/`taxonID`-as-name, largely time-invariant.

- **Validity** is a taxonomic *opinion*, relative to a stated classification, and is expected to change as revisions are published. An available name can be valid under one author's treatment and an invalid junior synonym under another's, in the same year. Model this as **Darwin Core `taxonomicStatus`** (`accepted`, `synonym`, `heterotypic synonym`, …), scoped to a particular taxonomic checklist/source, and versioned or dated to that source — never merged into the same column as nomenclatural status.
- Practical consequence for schema design: a name row can be `nomenclaturalStatus = available` while simultaneously appearing in ten different checklists with ten different `taxonomicStatus` values (accepted in one, synonym in nine) — these are two separate one-to-many relationships, not one field with contradictory values. See `references/data-modeling.md` for the recommended name-vs-taxon-concept table split, and `references/dwc-mapping.md` for the field-by-field Darwin Core crosswalk (including why `nomenclaturalStatus` should also carry availability-defeating conditions such as "nomen oblitum" or Commission suppressions, while `taxonomicStatus` never should).
